Scoring support and complete coverage Exact files, weighting and complete-case rules

Submissions are currently closed.

Final predictions must cover the complete reference support. For every scored case, this means every required entity, exactly once, in the actual field-bearing mesh or curve file from the named public dataset release. FluidsBench binds those files, their ordering, any masks, and their hashes to the scoring-support release. A method may infer on another representation and may process a large file in chunks, but it must map its predictions back to every required reference entity before calculating the final metrics. Downsampled or partially covered predictions are not complete results.

How to calculate large cases

    {% if include.slug == "drivaerml" %}
  • DrivAerML uses area-weighted relative L2 as the primary surface value and equal-native-polygon relative L2 as its secondary surface value. Its native volume fields use equal-native-cell relative L2 only; the candidate contract deliberately does not require geometric cell-volume weights.
  • Use the public boundary_cell_area_<run>.npy value for each surface polygon in the identical native VTP cell order. Each volume cell contributes one equal unit to the volume numerator and denominator.
    • {% elsif include.slug == "hiliftaeroml" %}
  • Use the published native nodal dual area for primary surface relative L2, and retain equal-node surface relative L2 as a secondary diagnostic. Each retained valid volume point contributes one unit weight; this candidate has no dual-volume weighting requirement.
  • Score relative errors on (P-p_inf)/q_inf, tau_wall/q_inf and U/|U_inf|. For vector relative L2, one point weight multiplies the squared three-component magnitude. Apply the raw volume validity mask before normalization and preserve the retained raw point IDs through chunking.
    • {% else %}
  • Surface and one-dimensional curve fields use area- or length-weighted relative L2 as the primary value and unweighted relative L2 as the secondary value. Two- and three-dimensional flow domains reverse that order: unweighted relative L2 is primary and area- or volume-weighted relative L2 is secondary. “Unweighted” means that every scored point, node, face, polygon, or cell counts equally.
  • Face- or cell-associated fields use the face area, cell area, or cell volume directly. For PointData or CGNS Vertex fields, FluidsBench supplies the area, volume, or curve length represented by each point or vertex, derived from the same reference mesh connectivity.
    • {% endif %}
  • In one pass over each case, accumulate the squared-error numerator and ground-truth denominator for every relative-L2 variant required in the table above, together with the corresponding entity count and total physical measure wherever one is used. Chunks may be any convenient size, but their numerators and denominators must be summed before taking the square root; never average chunk-level L2 values.
  • Calculate each complete-case percentage first, then macro-average the case percentages so every case counts equally.

Sharing complete prediction fields is optional. A contributor may link versioned predictions in an external public repository, but the submission package records exact coverage plus the per-case sufficient statistics used to reproduce each required relative-L2 value.
