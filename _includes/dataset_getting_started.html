For leaderboard work, always use the separate scoring source pin and case lists in the FluidsBench benchmark specification.

{% case include.slug %} {% when "ahmedml" %}

1. Inspect the metadata and splits

python3 -m pip install -U huggingface_hub hf_xet

2. Download and inspect one surface case

hf download neashton/ahmedml \
  --repo-type dataset \
  --revision {{ dataset.source.revision }} \
  --include "run_1/ahmed_1.stl" \
  --include "run_1/boundary_1.vtp" \
  --include "run_1/boundary_cell_area_1.npy" \
  --include "run_1/force_mom_1.csv" \
  --local-dir ./ahmedml
import numpy as np
import pyvista as pv

surface = pv.read("ahmedml/run_1/boundary_1.vtp")
area = np.load("ahmedml/run_1/boundary_cell_area_1.npy", mmap_mode="r")

print(surface.cell_data.keys())

The boundary fields are cell-associated, so sidecar entry i weights native polygon i. Download run_1/volume_1.vtu only when you are ready for the multi-gigabyte native volume; FluidsBench volume metrics cover every field-bearing cell.

Native volume files are transported as ordered .00.part, .01.part, and, for ten cases, .02.part segments. Resolve the exact list from proposal/native-source-pin.json, byte-concatenate it without delimiters, and process the reconstructed VTU in bounded chunks. Do not assume every case has two parts, resample the scoring support, or average chunk-level errors; accumulate numerators, denominators, and counts before the case-level reduction. Use force_mom_constref_<run>.csv for the benchmark force convention.

{% when "airfrans" %}

1. Install and download with the official library

python3 -m pip install "airfrans==0.1.5.1"

import airfrans as af
af.dataset.download(root="./airfrans_data", unzip=True)

2. Load an official task

import airfrans as af

train, train_names = af.dataset.load(
    root="./airfrans_data",
    task="full",
    train=True,
)
print(train.shape, train_names[:3])

The library task names are full, scarce, reynolds, and aoa. FluidsBench uses the corresponding published case lists but evaluates predictions on the complete released VTK supports. The source loader exposes nut; the current FluidsBench definition deliberately scores only U and p in the flow domain, plus derived boundary quantities and the four fixed velocity profiles.

  "https://dataverse.harvard.edu/api/datasets/:persistentId/?persistentId=doi:10.7910/DVN/VJT9EP" \

2. Download the version 1.0 archive

curl -L --continue-at - \
  "https://dataverse.harvard.edu/api/access/datafile/11905766" \
  -o "BlendedNet Dataset - Released.zip"

The public release is one 24.7 GB archive, so there is no metadata-only per-case transfer. Inspect the companion official loader and baseline repository before extracting it. The current FluidsBench geometry-holdout IDs are a proposal, not a separately published Dataverse split.

{% when "rotor37" %}

1. Install the Hub and PLAID readers

python3 -m pip install -U datasets pyplaid

On macOS or Windows, the PLAID project recommends its conda-forge package because the PyPI wheel is Linux-only.

2. Load one pinned training sample

from datasets import load_dataset
from plaid.bridges.huggingface_bridge import huggingface_dataset_to_plaid

rows = load_dataset(
    "PLAID-datasets/Rotor37",
    split="all_samples[:1]",
    revision="{{ dataset.source.revision }}",
)
samples, problem = huggingface_dataset_to_plaid(rows, processes_number=1)
print(problem)

Use the published index sequences for the nested 8-to-1,000 training regimes. The source rows numbered 1,000–1,199 omit targets; they are useful for the original hidden-target benchmark but cannot serve as FluidsBench's public-ground-truth evaluation set.
