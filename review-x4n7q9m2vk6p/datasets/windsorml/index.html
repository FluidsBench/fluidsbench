WindsorML dataset

Dataset overview and leaderboard submission format for WindsorML.

Automotive external aerodynamics

Overview

High-fidelity wall-modelled LES data for 355 designed Windsor-body variants, with approximately 300 million cells per simulation and time-averaged boundary, volume, geometry, force, slice, and image products.

FluidsBench evaluation schematic

  1. Model inputs Windsor geometry + WMLES conditions
  2. Scoring support Native boundary points and native volume cells
  3. Reported evaluation Area-weighted surface errors; equal-cell volume errors; forces and profiles

Technical details

Scoring source pin: Hugging Face revision 8a6ca32. Open contract.

What the source contains

STL and STEP geometry, native boundary and volume VTUs, force and geometry tables, flow images, eight split families, and native point dual-area sidecars for all 350 available boundary meshes. Runs 350–354 remain in aggregate split metadata but lack complete per-run geometry and image assets.

What FluidsBench currently evaluates

All eight Hugging Face splits are bound to the available native field files. Ground-truth profiles cover all 233 distinct test cases, with fixed and body-height-relative families. No model results are published. Public submissions remain closed pending owner review and completion of the submission workflow.

Dataset summary

Geometry
Geometric variants of the Windsor body, a simplified automotive bluff-body configuration.
Cases
355 designed cases; 350 public per-run field datasets.
Solver
Volcano Platforms GPU-native Cartesian immersed-boundary CFD solver.
Fidelity
Wall-Modelled Large-Eddy Simulation (WMLES), run transiently for approximately 80 convective time units.
Mesh scale
Approximately 300 million cells per case, with the paper describing meshes above 280 million cells.
Included data
Aggregate metadata for 355 cases and complete per-run geometry, fields, images, forces, and boundary weights for runs 0–349.
License
CC-BY-SA, as stated by the dataset paper and dataset source.

Getting started

Start with the source documentation and split metadata, then download one representative case before planning a full transfer. The commands below pin the source snapshot audited for this page. For leaderboard work, always use the separate scoring source pin and case lists in the FluidsBench benchmark specification.

1. Inspect the source coverage

python3 -m pip install -U huggingface_hub hf_xet
hf download neashton/windsorml \
  --repo-type dataset \
  --revision 8a6ca32ae22c94f54df2186d1b0ccf9662a294c2 \
  --include "README.md" \
  --include "splits/**" \
  --include "surface_dual_areas/**" \
  --local-dir ./windsorml \
  --dry-run

2. Download one complete field case

hf download neashton/windsorml \
  --repo-type dataset \
  --revision 8a6ca32ae22c94f54df2186d1b0ccf9662a294c2 \
  --include "run_1/windsor_1.stl" \
  --include "run_1/boundary_1.vtu" \
  --include "run_1/boundary_dual_area_1.npy" \
  --include "run_1/force_mom_1.csv" \
  --local-dir ./windsorml
import numpy as np
import pyvista as pv

surface = pv.read("windsorml/run_1/boundary_1.vtu")
area = np.load("windsorml/run_1/boundary_dual_area_1.npy", mmap_mode="r")
assert area.shape == (surface.n_points,)
print(surface.point_data.keys())

Remove --dry-run only after checking the transfer size. The dual areas apply to the exact raw VTU point order. The split metadata covers 355 aggregate cases, but only runs 0–349 currently have complete per-run field folders and area sidecars; an official FluidsBench field split must exclude or otherwise resolve the five incomplete cases explicitly.

Conditions and sampling

Operating conditions

All cases use the AutoCFD wind-tunnel-style setup at nominal 40 m/s, Reynolds number 2.9 × 10⁶, and 2.5° yaw; flow conditions are fixed.

Sampling

A deterministic, extendable Halton sequence samples 355 points in the seven-dimensional geometry space; complete per-run fields are available for 350.

Open-reproducibility submission Files, validation and optional artifacts

Check this dataset's current submission status on the leaderboard before preparing a result. Contributions are accepted only while its exact scoring-support release is marked official and open. For an open dataset, contributors propose one result directory at submissions/windsorml/<submission-id>/ in the FluidsBench submission repository. The planned result package contains:

  • submission.json for model metadata and the required scalar metrics;
  • evaluation-evidence.json linking those submitter-provided metrics to the declared evaluation revision and profile-index checksum;
  • discretization.json describing the training input and supervision supports, inference input, direct model outputs, and mapping to the official scoring support;
  • discretization/cases.jsonl recording case-level counts, domains, mapping, and declared scoring coverage;
  • metrics/cases.json recording the official-support errors, the unweighted and physical-measure-weighted sufficient statistics required by that dataset's contract, and exact coverage for every declared evaluation case;
  • profiles/index.json listing the lightweight profile chunks; and
  • profiles/chunk-*.json containing profile coordinates and predictions for the declared test cases.

FluidsBench uses an open reproducibility track. The declared evaluation partition, scored case lists, and ground truth are public. Evaluation cases must not be used for fitting, hyperparameter selection, or preprocessing statistics. Contributors will calculate the metrics and extract the profiles from their own predictions. Each dataset specification fixes the locations, IDs, weights, targets, and coverage used for final scoring. A model may infer on a different point set, mesh, or grid, but its final predictions must be mapped onto every required entity in the release-bound public field files before the reference evaluator calculates the errors. Large cases may be processed in chunks, but contributors must sum the sufficient statistics across all chunks before calculating a case metric; chunk-level L2 values are never averaged. Leaderboard field errors are calculated on the declared evaluation/test cases, not on the training cases. Full meshes and volume fields are not committed to the submission repository. Contributors may optionally publish example cases or the complete scored predictions in a public, immutable external repository and link that artifact from the submission. Use the WindsorML benchmark specification for the exact split, metric, case, panel, station, and quantity IDs. The reference equations and code define how the scalar values must be calculated, and the worked examples show the JSON structure.

Before opening a pull request, run python scripts/validate_submission.py --contributor-stage submissions/windsorml/<submission-id>. The validator checks the schema, split identity, scoring-support binding, derived-score arithmetic, profile coverage, reported discretization, array lengths, ordering, finite values, and file hashes. It checks the submitted package's internal consistency; it does not run the contributor's model or recalculate base metrics from full fields.

A passing validator or pull request will not make a result official. Official results require maintainer approval of the validated submission package. Public code, model, and environment artifacts and their documentation are optional. If supplied, they must use stable links and include the revisions, digests, and licences required by the submission schema; the leaderboard reports those details. Their absence does not change accuracy rank, citation eligibility, or promotion eligibility. Prediction sharing is also optional. When prediction artifacts are shared, the leaderboard separately reports their coverage, artifact-check status, and whether any metrics were recomputed; it does not collapse those distinct checks into a generic “verified” badge. The public validation record states exactly what FluidsBench checked.

Prototype notice: any case IDs, ground truth, profile values, or leaderboard rows labelled prototype are illustrative dummy data. Those materials must be replaced and finalized before the dataset opens; a prototype row is never an official result.

Scoring support and complete coverage Exact files, weighting and complete-case rules

Submissions are currently closed.

Final predictions must cover the complete reference support. For every scored case, this means every required entity, exactly once, in the actual field-bearing mesh or curve file from the named public dataset release. FluidsBench binds those files, their ordering, any masks, and their hashes to the scoring-support release. A method may infer on another representation and may process a large file in chunks, but it must map its predictions back to every required reference entity before calculating the final metrics. Downsampled or partially covered predictions are not complete results.

Scored support Public field file and association Required coverage Relative-L2 pair
Three-dimensional body boundary run_<case-id>/boundary_<case-id>.vtu; cpavg and cfxavg/cfyavg/cfzavg in VTK PointData; matching point dual areas are in boundary_dual_area_<case-id>.npy for the 350 complete public field cases Every point carrying the scored pressure and skin-friction coefficients Area-weighted primary; unweighted point (each point counts equally) secondary
Three-dimensional flow volume run_<case-id>/volume_<case-id>.vtu; velocityxavg, velocityyavg, velocityzavg, and pressureavg in VTK CellData Every cell carrying those velocity components and pressure Equal native cell only; the candidate contract does not use cell-volume weights

How to calculate large cases

  • Surface and one-dimensional curve fields use area- or length-weighted relative L2 as the primary value and unweighted relative L2 as the secondary value. Two- and three-dimensional flow domains reverse that order: unweighted relative L2 is primary and area- or volume-weighted relative L2 is secondary. “Unweighted” means that every scored point, node, face, polygon, or cell counts equally.
  • Face- or cell-associated fields use the face area, cell area, or cell volume directly. For PointData or CGNS Vertex fields, FluidsBench supplies the area, volume, or curve length represented by each point or vertex, derived from the same reference mesh connectivity.
  • In one pass over each case, accumulate the squared-error numerator and ground-truth denominator for every relative-L2 variant required in the table above, together with the corresponding entity count and total physical measure wherever one is used. Chunks may be any convenient size, but their numerators and denominators must be summed before taking the square root; never average chunk-level L2 values.
  • Calculate each complete-case percentage first, then macro-average the case percentages so every case counts equally.

Sharing complete prediction fields is optional. A contributor may link versioned predictions in an external public repository, but the submission package records exact coverage plus the per-case sufficient statistics used to reproduce each required relative-L2 value.

Metric definitions

Relative L2 error
For each evaluation/test geometry, map predictions to every entity in the release-bound public field support and undo any training normalization. Calculate both paired relative-L2 values from the accumulated sufficient statistics: area-weighted L2 is primary on the boundary, while unweighted cell L2 (each cell counts equally) is primary in the flow volume. Report the complete-case percentages first, then take the arithmetic mean of the geometry-level values.
Relative L1 error
When reported as a supplementary metric, relative L1 uses the same complete dimensional support and the primary weighting for that domain. Calculate a percentage for each geometry, then take the arithmetic mean of the geometry-level percentages.
Dataset-native evaluation
The boundary arrays are the dimensionless coefficients cpavg, cfxavg, cfyavg, and cfzavg, not pressure or wall shear in pascals. Volume fields are scored in their release-bound dataset-native representation. Any normalization used for training must be undone first.
Surface pressure-coefficient relative L1/L2
Relative L1 and paired relative L2 error for cpavg at every point in the public boundary VTU.
Surface skin-friction-coefficient relative L1/L2
Relative L1 and paired relative L2 error for the coefficient vector (cfxavg, cfyavg, cfzavg) at every public boundary point.
Volume velocity relative L1/L2
Relative L1 and L2 error for the velocity vector \(u = (u_x, u_y, u_z)\) on every field-bearing cell in the release-bound public volume VTU.
Volume pressure relative L1/L2
Relative L1 and L2 error for pressure on every field-bearing cell in the same public volume VTU.
AB-UPT convention
The secondary unweighted point relative L2 (each point counts equally) follows the AB-UPT-compatible convention used for AhmedML and DrivAerML: targets may be normalized for training, but evaluation uses unnormalized predictions and targets. FluidsBench uses the area-weighted boundary value as its primary surface metric. AB-UPT v2 does not report WindsorML numbers.
Coefficient of determination
For scalar values \(y_i\), \(R^2 = 1 - \sum_i(\hat{y}_i - y_i)^2 / \sum_i(y_i - \bar{y})^2\). Higher is better; 1.0 is perfect.
Cd and Cl R2
R2 over all evaluated cases. The evaluator integrates predicted and reference Cp and skin-friction fields using the same boundary support, reference area of 0.112 m², and +y lift convention.
Force R2
Mean of Cd R2 and Cl R2.
Cp cut R2
One global R2 over all selected surface pressure coefficient samples from the held-out test cases. The evaluator flattens cp_pred and ground-truth cp across case_id, cut_id, station_id, and cut sample locations before computing R2. The plotted trace is chosen with the leaderboard station selector.
Cp cut comparisons
Per-case and per-cut R2 values can be reported as profile comparisons, but the leaderboard ranking should use the global held-out score so that cases with low Cp variance do not dominate through unstable per-case averages.
Velocity profile R2
One global R2 for streamwise velocity u_x / U_inf, with U_inf = 42.1 m/s, across all five fixed stations, test cases, and 128 samples per station. The body-height-relative result is reported separately at zero weight.
