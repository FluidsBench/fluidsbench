Dataset overview and leaderboard submission format for DrivAerNet++.

Automotive external aerodynamics

Overview

A large multimodal automotive-aerodynamics collection with 8,150 vehicle designs spanning fastback, notchback, and estateback categories, including surface and volume CFD, meshes, coefficients, annotations, point clouds, and rendered or sketched geometry representations.

Technical details

Scoring source pin: Dataverse DOI 10.7910/DVN/K7PWNJ, version 1.0. Open contract.

What the source contains

Volume fields, surface pressure and wall-shear data, point clouds, meshes, aerodynamic coefficients, design annotations, and visual modalities. FluidsBench currently has a pressure-only candidate task tied to Dataverse DOI 10.7910/DVN/K7PWNJ v1.0.

What FluidsBench currently evaluates

The active dev contract is still a one-case prototype. It scores kinematic surface pressure p at every native VTK PointData location with area-weighted relative L2 as primary and equal-point relative L2 as secondary. It does not yet activate the reviewed 1,154-case test proposal, wall shear, volume fields, forces, or profiles.

Getting started

Start with the source documentation and split metadata, then download one representative case before planning a full transfer. The commands below pin the source snapshot audited for this page. For leaderboard work, always use the separate scoring source pin and case lists in the FluidsBench benchmark specification.

1. Inspect the pressure-release metadata

curl -L \
  "https://dataverse.harvard.edu/api/datasets/:persistentId/?persistentId=doi:10.7910/DVN/K7PWNJ" \
  -o drivaernetplusplus-pressure-metadata.json

2. Plan a resumable archive transfer

# Example: one public pressure archive (about 18.4 GB)
curl -L --continue-at - \
  "https://dataverse.harvard.edu/api/access/datafile/10816644" \
  -o E_S_WWC_WM.zip

Use the project's Dataverse or Globus instructions for the full collection. The current FluidsBench converter reads the public VTK pressure array p as kinematic pressure in m²/s² and maps every native point into the scoring table. The active contract still has only one prototype case; do not treat the 1,154-car proposal as open until its split and scoring-support release are finalized and merged.

Conditions and sampling

Operating conditions

The CFD condition is fixed at 30 m/s. Geometry-dependent vehicle length gives a reported Reynolds-number range of 8.366 × 10⁶ to 1.006 × 10⁷ rather than a separately sampled flow sweep.

Sampling

Optimal Latin hypercube sampling with an enhanced stochastic evolutionary algorithm populates the mixed continuous/discrete design space; the current canonical collection lists 8,150 designs.

Open-reproducibility submission Files, validation and optional artifacts

Check this dataset's current submission status on the leaderboard before preparing a result. Contributions are accepted only while its exact scoring-support release is marked official and open. For an open dataset, contributors propose one result directory at submissions/drivaernetplusplus/<submission-id>/ in the FluidsBench submission repository. The planned result package contains:

  • submission.json for model metadata and the required scalar metrics;
  • evaluation-evidence.json linking those submitter-provided metrics to the declared evaluation revision and profile-index checksum;
  • discretization.json describing the training input and supervision supports, inference input, direct model outputs, and mapping to the official scoring support;
  • discretization/cases.jsonl recording case-level counts, domains, mapping, and declared scoring coverage;
  • metrics/cases.json recording the official-support errors, the unweighted and physical-measure-weighted sufficient statistics required by that dataset's contract, and exact coverage for every declared evaluation case;
  • profiles/index.json listing the lightweight profile chunks; and
  • profiles/chunk-*.json containing profile coordinates and predictions for the declared test cases.

FluidsBench uses an open reproducibility track. The declared evaluation partition, scored case lists, and ground truth are public. Evaluation cases must not be used for fitting, hyperparameter selection, or preprocessing statistics. Contributors will calculate the metrics and extract the profiles from their own predictions. Each dataset specification fixes the locations, IDs, weights, targets, and coverage used for final scoring. A model may infer on a different point set, mesh, or grid, but its final predictions must be mapped onto every required entity in the release-bound public field files before the reference evaluator calculates the errors. Large cases may be processed in chunks, but contributors must sum the sufficient statistics across all chunks before calculating a case metric; chunk-level L2 values are never averaged. Leaderboard field errors are calculated on the declared evaluation/test cases, not on the training cases. Full meshes and volume fields are not committed to the submission repository. Contributors may optionally publish example cases or the complete scored predictions in a public, immutable external repository and link that artifact from the submission. Use the DrivAerNet++ benchmark specification for the exact split, metric, case, panel, station, and quantity IDs. The reference equations and code define how the scalar values must be calculated, and the worked examples show the JSON structure.

Before opening a pull request, run python scripts/validate_submission.py --contributor-stage submissions/drivaernetplusplus/<submission-id>. The validator checks the schema, split identity, scoring-support binding, derived-score arithmetic, profile coverage, reported discretization, array lengths, ordering, finite values, and file hashes. It checks the submitted package's internal consistency; it does not run the contributor's model or recalculate base metrics from full fields.

A passing validator or pull request will not make a result official. Official results require maintainer approval of the validated submission package. Public code, model, and environment artifacts and their documentation are optional. If supplied, they must use stable links and include the revisions, digests, and licences required by the submission schema; the leaderboard reports those details. Their absence does not change accuracy rank, citation eligibility, or promotion eligibility. Prediction sharing is also optional. When prediction artifacts are shared, the leaderboard separately reports their coverage, artifact-check status, and whether any metrics were recomputed; it does not collapse those distinct checks into a generic “verified” badge. The public validation record states exactly what FluidsBench checked.

Prototype notice: any case IDs, ground truth, profile values, or leaderboard rows labelled prototype are illustrative dummy data. Those materials must be replaced and finalized before the dataset opens; a prototype row is never an official result.

Scoring support and complete coverage Exact files, weighting and complete-case rules

Submissions are currently closed.

Final predictions must cover the complete reference support. For every scored case, this means every required entity, exactly once, in the actual field-bearing mesh or curve file from the named public dataset release. FluidsBench binds those files, their ordering, any masks, and their hashes to the scoring-support release. A method may infer on another representation and may process a large file in chunks, but it must map its predictions back to every required reference entity before calculating the final metrics. Downsampled or partially covered predictions are not complete results.

Scored support Public field file and association Required coverage Relative-L2 pair
Three-dimensional vehicle surface SurfacePressureVTK/<design>.vtk in Dataverse DOI 10.7910/DVN/K7PWNJ, array p in VTK PointData Every surface point carrying p Area-weighted primary; unweighted point (each point counts equally) secondary
Surface pressure is the confirmed task. Wall shear and full-volume CFD fields are not scored until their public files and field associations are confirmed in a later scoring-support release.

How to calculate large cases

  • Surface and one-dimensional curve fields use area- or length-weighted relative L2 as the primary value and unweighted relative L2 as the secondary value. Two- and three-dimensional flow domains reverse that order: unweighted relative L2 is primary and area- or volume-weighted relative L2 is secondary. “Unweighted” means that every scored point, node, face, polygon, or cell counts equally.
  • Face- or cell-associated fields use the face area, cell area, or cell volume directly. For PointData or CGNS Vertex fields, FluidsBench supplies the area, volume, or curve length represented by each point or vertex, derived from the same reference mesh connectivity.
  • In one pass over each case, accumulate the squared-error numerator and ground-truth denominator for every relative-L2 variant required in the table above, together with the corresponding entity count and total physical measure wherever one is used. Chunks may be any convenient size, but their numerators and denominators must be summed before taking the square root; never average chunk-level L2 values.
  • Calculate each complete-case percentage first, then macro-average the case percentages so every case counts equally.

Sharing complete prediction fields is optional. A contributor may link versioned predictions in an external public repository, but the submission package records exact coverage plus the per-case sufficient statistics used to reproduce each required relative-L2 value.

Metric definitions

Relative L2 error
For each case, map dataset-native kinematic-pressure predictions to every point carrying p in the release-bound VTK surface. FluidsBench reports an area-weighted relative L2 as primary and unweighted point relative L2 (each point counts equally) as secondary. Calculate each complete-case percentage first, then macro-average the cases.
Relative L1 error
When reported as a supplementary metric, relative L1 uses every required pressure point and the same dual-area weighting as the primary relative L2.
Surface pressure relative L2
CarBench reports an unweighted point relative L2 (each point counts equally) on the DrivAerNet++ geometry-disjoint evaluation set. FluidsBench displays that source-paper value only as a prototype for the unweighted point secondary metric; the primary area-weighted value requires a complete evaluator rerun.
Pressure-field R2
Coefficient of determination over flattened surface pressure samples: 1 - sum((q_pred - q_true)^2) / sum((q_true - mean(q_true))^2).

For the current prototype release, leaderboard rank uses the higher-is-better composite score overall_score = clip(100 - surface_pressure_rel_l2, 0, 100), where surface_pressure_rel_l2 is the primary area-weighted percentage error. This provisional transformation preserves the ordering of the underlying pressure error while giving every FluidsBench dataset the same ranking-column ID. The original pressure metrics remain visible alongside it.

CarBench values used in the prototype

The current leaderboard rows use CarBench Table 1 values for surface pressure relative L2, pressure-field R2, and parameter count. The paper states that its first release focuses on surface pressure and does not evaluate drag/lift coefficients or volumetric fields, so those unsupported fields have been removed from the active prototype metric contract. Absolute pressure MAE/RMSE are also disabled until the release-bound unit convention is confirmed. The source relative L2 is treated as an unweighted point prototype, not as the final area-weighted primary metric.
