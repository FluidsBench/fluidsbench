BlendedNet dataset

Dataset overview and leaderboard submission format for BlendedNet.

Blended-wing-body aerodynamics

Overview

A public surface-aerodynamics dataset with 999 unique blended-wing-body geometries and 8,830 converged steady RANS cases across geometry and flight-condition variation, using 9–14 million volume cells per simulation.

Technical details

Scoring source pin: Dataverse DOI 10.7910/DVN/VJT9EP, version 1.0. Open contract.

What the source contains

Nine geometric design parameters, flight conditions, point coordinates and normals, surface pressure and skin-friction coefficients, and integrated drag, lift, and pitching-moment coefficients. The public reference model uses Cp, Cfx, and Cfz; the raw VTK conversion also exposes cf_y when present.

What FluidsBench currently evaluates

The candidate task is surface-only and uses cp plus cf_x/cf_y/cf_z on every native legacy-VTK surface point, with area-weighted relative L2 as the primary physical metric. The current 870-case geometry-holdout list is provisional; the public Dataverse release does not separately identify it as an official evaluation release, so this mapping is not active for submissions.

Getting started

Start with the source documentation and split metadata, then download one representative case before planning a full transfer. The commands below pin the source snapshot audited for this page. For leaderboard work, always use the separate scoring source pin and case lists in the FluidsBench benchmark specification.

1. Inspect the immutable Dataverse metadata

curl -L \
  "https://dataverse.harvard.edu/api/datasets/:persistentId/?persistentId=doi:10.7910/DVN/VJT9EP" \
  -o blendednet-dataverse.json

2. Download the version 1.0 archive

curl -L --continue-at - \
  "https://dataverse.harvard.edu/api/access/datafile/11905766" \
  -o "BlendedNet Dataset - Released.zip"

The public release is one 24.7 GB archive, so there is no metadata-only per-case transfer. Inspect the companion official loader and baseline repository before extracting it. The current FluidsBench geometry-holdout IDs are a proposal, not a separately published Dataverse split.

Conditions and sampling

Operating conditions

Flight-condition sampling spans altitude 0–40 kft, Mach 0.05–0.5, Reynolds reference length 0.1–10 m, and angle of attack −10° to 20°.

Sampling

Latin hypercube sampling produces 999 planforms and approximately nine flight conditions per geometry, with 8,830 simulations converging successfully.

Open-reproducibility submission Files, validation and optional artifacts

Check this dataset's current submission status on the leaderboard before preparing a result. Contributions are accepted only while its exact scoring-support release is marked official and open. For an open dataset, contributors propose one result directory at submissions/blendednet/<submission-id>/ in the FluidsBench submission repository. The planned result package contains:

  • submission.json for model metadata and the required scalar metrics;
  • evaluation-evidence.json linking those submitter-provided metrics to the declared evaluation revision and profile-index checksum;
  • discretization.json describing the training input and supervision supports, inference input, direct model outputs, and mapping to the official scoring support;
  • discretization/cases.jsonl recording case-level counts, domains, mapping, and declared scoring coverage;
  • metrics/cases.json recording the official-support errors, the unweighted and physical-measure-weighted sufficient statistics required by that dataset's contract, and exact coverage for every declared evaluation case;
  • profiles/index.json listing the lightweight profile chunks; and
  • profiles/chunk-*.json containing profile coordinates and predictions for the declared test cases.

FluidsBench uses an open reproducibility track. The declared evaluation partition, scored case lists, and ground truth are public. Evaluation cases must not be used for fitting, hyperparameter selection, or preprocessing statistics. Contributors will calculate the metrics and extract the profiles from their own predictions. Each dataset specification fixes the locations, IDs, weights, targets, and coverage used for final scoring. A model may infer on a different point set, mesh, or grid, but its final predictions must be mapped onto every required entity in the release-bound public field files before the reference evaluator calculates the errors. Large cases may be processed in chunks, but contributors must sum the sufficient statistics across all chunks before calculating a case metric; chunk-level L2 values are never averaged. Leaderboard field errors are calculated on the declared evaluation/test cases, not on the training cases. Full meshes and volume fields are not committed to the submission repository. Contributors may optionally publish example cases or the complete scored predictions in a public, immutable external repository and link that artifact from the submission. Use the BlendedNet benchmark specification for the exact split, metric, case, panel, station, and quantity IDs. The reference equations and code define how the scalar values must be calculated, and the worked examples show the JSON structure.

Before opening a pull request, run python scripts/validate_submission.py --contributor-stage submissions/blendednet/<submission-id>. The validator checks the schema, split identity, scoring-support binding, derived-score arithmetic, profile coverage, reported discretization, array lengths, ordering, finite values, and file hashes. It checks the submitted package's internal consistency; it does not run the contributor's model or recalculate base metrics from full fields.

A passing validator or pull request will not make a result official. Official results require maintainer approval of the validated submission package. Public code, model, and environment artifacts and their documentation are optional. If supplied, they must use stable links and include the revisions, digests, and licences required by the submission schema; the leaderboard reports those details. Their absence does not change accuracy rank, citation eligibility, or promotion eligibility. Prediction sharing is also optional. When prediction artifacts are shared, the leaderboard separately reports their coverage, artifact-check status, and whether any metrics were recomputed; it does not collapse those distinct checks into a generic “verified” badge. The public validation record states exactly what FluidsBench checked.

Prototype notice: any case IDs, ground truth, profile values, or leaderboard rows labelled prototype are illustrative dummy data. Those materials must be replaced and finalized before the dataset opens; a prototype row is never an official result.

Scoring support and complete coverage Exact files, weighting and complete-case rules

Submissions are currently closed.

Final predictions must cover the complete reference support. For every scored case, this means every required entity, exactly once, in the actual field-bearing mesh or curve file from the named public dataset release. FluidsBench binds those files, their ordering, any masks, and their hashes to the scoring-support release. A method may infer on another representation and may process a large file in chunks, but it must map its predictions back to every required reference entity before calculating the final metrics. Downsampled or partially covered predictions are not complete results.

Scored support Public field file and association Required coverage Relative-L2 pair
Three-dimensional aircraft surface Released legacy VTK POLYDATA, arrays cp, cf_x, cf_y, and cf_z in PointData Every surface vertex carrying each scored coefficient Area-weighted primary; unweighted vertex (each vertex counts equally) secondary
The current public FluidsBench field task is surface-only; it does not invent a volume target.

How to calculate large cases

  • Surface and one-dimensional curve fields use area- or length-weighted relative L2 as the primary value and unweighted relative L2 as the secondary value. Two- and three-dimensional flow domains reverse that order: unweighted relative L2 is primary and area- or volume-weighted relative L2 is secondary. “Unweighted” means that every scored point, node, face, polygon, or cell counts equally.
  • Face- or cell-associated fields use the face area, cell area, or cell volume directly. For PointData or CGNS Vertex fields, FluidsBench supplies the area, volume, or curve length represented by each point or vertex, derived from the same reference mesh connectivity.
  • In one pass over each case, accumulate the squared-error numerator and ground-truth denominator for every relative-L2 variant required in the table above, together with the corresponding entity count and total physical measure wherever one is used. Chunks may be any convenient size, but their numerators and denominators must be summed before taking the square root; never average chunk-level L2 values.
  • Calculate each complete-case percentage first, then macro-average the case percentages so every case counts equally.

Sharing complete prediction fields is optional. A contributor may link versioned predictions in an external public repository, but the submission package records exact coverage plus the per-case sufficient statistics used to reproduce each required relative-L2 value.

Leaderboard metrics

The primary field error is the mean area-weighted relative L2 across Cp, Cfx, Cfy, and Cfz. Every field is evaluated at every vertex in the released VTK POLYDATA surface. An unweighted vertex relative L2 (each vertex counts equally) is reported alongside each primary value for source-paper and point-model comparison. Lower field error is better. The four-field aggregate is a FluidsBench display rule; the paper reports component metrics separately.

MSE = (1/N) sum_i (yhat_i-y_i)^2

MAE = (1/N) sum_i |yhat_i-y_i|

L1_rel(%) = 100 sum_i |yhat_i-y_i| / sum_i |y_i|

L2_rel(w, %) = 100 sqrt(sum_i w_i (yhat_i-y_i)^2) / sqrt(sum_i w_i y_i^2)

Use deterministic mass-lumped dual surface areas for the primary value and w_i = 1 for the secondary unweighted vertex value. Compute each complete case before macro-averaging cases.

R2 = 1 - sum_i (y_i-yhat_i)^2 / sum_i (y_i-mean(y))^2

surface_mean_L2 = (area_L2_Cp + area_L2_Cfx + area_L2_Cfy + area_L2_Cfz) / 4

For the current prototype release, leaderboard rank uses the higher-is-better composite score overall_score = clip(100 - surface_mean_L2, 0, 100). This provisional transformation preserves the ordering of the underlying four-field error while giving every FluidsBench dataset the same ranking-column ID. The component errors remain available for interpretation and comparison.

Profile comparisons

BlendedNet publishes surface coefficient fields rather than full three-dimensional flow fields. The leaderboard therefore shows pressure and skin-friction cuts, but does not invent a velocity-profile comparison.

Current ground-truth and submitted curves are clearly labelled illustrative dummy data. They must be replaced once FluidsBench publishes a canonical case, extraction coordinates, interpolation rule, and tolerance for each cut.
