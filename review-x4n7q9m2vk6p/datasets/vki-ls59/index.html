VKI-LS59 dataset

Dataset overview and leaderboard submission format for VKI-LS59.

Turbine-cascade aerodynamics

Overview

A PLAID-formatted collection of 839 two-dimensional compressible RANS simulations of the LS59 turbine cascade, spanning inlet incidence and outlet Mach number with geometry, signed-distance, field, curve, and scalar quantities.

FluidsBench evaluation schematic

  1. Model inputs Cascade geometry + signed distance + incidence + outlet Mach
  2. Scoring support Candidate complete 2D domain and blade curve
  3. Reported evaluation Equal-node domain errors; length-weighted M_iso; six scalar quantities

Schematic only; the benchmark specification fixes the exact files, entities, arrays, and equations.

Technical details

Scoring source pin: Not yet frozen. Open contract.

What the source contains

Geometry, signed distance, inlet angle and outlet Mach inputs; two-dimensional ro, rou, rov, roe, nut, and mach fields; blade-curve M_iso; and Q, power, Pr, Tr, eth_is, and angle_out scalars in the training population. Source evaluation outputs are hidden.

What FluidsBench currently evaluates

The candidate scores mach and nut on every native two-dimensional CGNS vertex, M_iso along every blade-curve vertex, and the six public scalar targets. Because the source 168-case evaluation targets are hidden, FluidsBench must publish and approve a separate public-ground-truth evaluation split; all eight current case lists are prototypes.

Getting started

Start with the source documentation and split metadata, then download one representative case before planning a full transfer. The commands below pin the source snapshot audited for this page. For leaderboard work, always use the separate scoring source pin and case lists in the FluidsBench benchmark specification.

1. Install the Hub and PLAID readers

python3 -m pip install -U datasets pyplaid

On macOS or Windows, the PLAID project recommends its conda-forge package because the PyPI wheel is Linux-only.

2. Load one pinned training sample

from datasets import load_dataset
from plaid.bridges.huggingface_bridge import huggingface_dataset_to_plaid

rows = load_dataset(
    "PLAID-datasets/VKI-LS59",
    split="all_samples[:1]",
    revision="1aad0a69c26462c039305a931a300f80bdf34827",
)
samples, problem = huggingface_dataset_to_plaid(rows, processes_number=1)
print(problem)

The nested training regimes use the first 8–671 entries of the published training sequence. The 168 source-evaluation rows omit their output fields and scalars, so FluidsBench needs a different public-ground-truth evaluation list before it can open submissions.

Open-reproducibility submission Files, validation and optional artifacts

Check this dataset's current submission status on the leaderboard before preparing a result. Contributions are accepted only while its exact scoring-support release is marked official and open. For an open dataset, contributors propose one result directory at submissions/vki-ls59/<submission-id>/ in the FluidsBench submission repository. The planned result package contains:

  • submission.json for model metadata and the required scalar metrics;
  • evaluation-evidence.json linking those submitter-provided metrics to the declared evaluation revision and profile-index checksum;
  • discretization.json describing the training input and supervision supports, inference input, direct model outputs, and mapping to the official scoring support;
  • discretization/cases.jsonl recording case-level counts, domains, mapping, and declared scoring coverage;
  • metrics/cases.json recording the official-support errors, the unweighted and physical-measure-weighted sufficient statistics required by that dataset's contract, and exact coverage for every declared evaluation case;
  • profiles/index.json listing the lightweight profile chunks; and
  • profiles/chunk-*.json containing profile coordinates and predictions for the declared test cases.

FluidsBench uses an open reproducibility track. The declared evaluation partition, scored case lists, and ground truth are public. Evaluation cases must not be used for fitting, hyperparameter selection, or preprocessing statistics. Contributors will calculate the metrics and extract the profiles from their own predictions. Each dataset specification fixes the locations, IDs, weights, targets, and coverage used for final scoring. A model may infer on a different point set, mesh, or grid, but its final predictions must be mapped onto every required entity in the release-bound public field files before the reference evaluator calculates the errors. Large cases may be processed in chunks, but contributors must sum the sufficient statistics across all chunks before calculating a case metric; chunk-level L2 values are never averaged. Leaderboard field errors are calculated on the declared evaluation/test cases, not on the training cases. Full meshes and volume fields are not committed to the submission repository. Contributors may optionally publish example cases or the complete scored predictions in a public, immutable external repository and link that artifact from the submission. Use the VKI-LS59 benchmark specification for the exact split, metric, case, panel, station, and quantity IDs. The reference equations and code define how the scalar values must be calculated, and the worked examples show the JSON structure.

Before opening a pull request, run python scripts/validate_submission.py --contributor-stage submissions/vki-ls59/<submission-id>. The validator checks the schema, split identity, scoring-support binding, derived-score arithmetic, profile coverage, reported discretization, array lengths, ordering, finite values, and file hashes. It checks the submitted package's internal consistency; it does not run the contributor's model or recalculate base metrics from full fields.

A passing validator or pull request will not make a result official. Official results require maintainer approval of the validated submission package. Public code, model, and environment artifacts and their documentation are optional. If supplied, they must use stable links and include the revisions, digests, and licences required by the submission schema; the leaderboard reports those details. Their absence does not change accuracy rank, citation eligibility, or promotion eligibility. Prediction sharing is also optional. When prediction artifacts are shared, the leaderboard separately reports their coverage, artifact-check status, and whether any metrics were recomputed; it does not collapse those distinct checks into a generic “verified” badge. The public validation record states exactly what FluidsBench checked.

Prototype notice: any case IDs, ground truth, profile values, or leaderboard rows labelled prototype are illustrative dummy data. Those materials must be replaced and finalized before the dataset opens; a prototype row is never an official result.

Scoring support and complete coverage Exact files, weighting and complete-case rules

Submissions are currently closed.

Final predictions must cover the complete reference support. For every scored case, this means every required entity, exactly once, in the actual field-bearing mesh or curve file from the named public dataset release. FluidsBench binds those files, their ordering, any masks, and their hashes to the scoring-support release. A method may infer on another representation and may process a large file in chunks, but it must map its predictions back to every required reference entity before calculating the final metrics. Downsampled or partially covered predictions are not complete results.

Scored support Public field file and association Required coverage Relative-L2 pair
Two-dimensional quadrilateral flow domain PLAID CGNS /Base_2_2/Zone; mach and nut at CGNS Vertex locations Every vertex carrying the scored mach and nut fields Unweighted vertex (each vertex counts equally) primary; area-weighted secondary
One-dimensional blade curve PLAID CGNS /Base_1_2/Zone; M_iso at CGNS Vertex locations Every ordered curve vertex carrying M_iso Length-weighted primary; unweighted vertex (each vertex counts equally) secondary
The source evaluation rows omit their targets. FluidsBench will therefore bind scoring to a separate evaluation split whose ground truth is public.

How to calculate large cases

  • Surface and one-dimensional curve fields use area- or length-weighted relative L2 as the primary value and unweighted relative L2 as the secondary value. Two- and three-dimensional flow domains reverse that order: unweighted relative L2 is primary and area- or volume-weighted relative L2 is secondary. “Unweighted” means that every scored point, node, face, polygon, or cell counts equally.
  • Face- or cell-associated fields use the face area, cell area, or cell volume directly. For PointData or CGNS Vertex fields, FluidsBench supplies the area, volume, or curve length represented by each point or vertex, derived from the same reference mesh connectivity.
  • In one pass over each case, accumulate the squared-error numerator and ground-truth denominator for every relative-L2 variant required in the table above, together with the corresponding entity count and total physical measure wherever one is used. Chunks may be any convenient size, but their numerators and denominators must be summed before taking the square root; never average chunk-level L2 values.
  • Calculate each complete-case percentage first, then macro-average the case percentages so every case counts equally.

Sharing complete prediction fields is optional. A contributor may link versioned predictions in an external public repository, but the submission package records exact coverage plus the per-case sufficient statistics used to reproduce each required relative-L2 value.

Leaderboard metrics

The current prototype retains total_error, the arithmetic mean of the PLAID RRMSE values for mach, nut, and the six scalar outputs, as a source-compatible display. On the future public-ground-truth FluidsBench split, the scored mach and nut domain fields will also have paired complete-domain relative-L2 values: unweighted vertex L2 (each vertex counts equally) is primary and area-weighted L2 is secondary. The one-dimensional M_iso curve reverses the order: length-weighted L2 is primary and unweighted vertex L2 is secondary. Calculate each case over every required vertex, then macro-average the cases. Lower total_error is better.

RRMSE_field = sqrt((1/n) sum_i [((1/N_i) ||fhat_i - f_i||_2^2) / ||f_i||_inf^2])

RRMSE_scalar = sqrt((1/n) sum_i [|shat_i - s_i|^2 / |s_i|^2])

total_error = (1/m) sum_j RRMSE_j

L1_rel(%) = 100 sum_i w_i |yhat_i-y_i| / sum_i w_i |y_i|

L2_rel(%) = 100 sqrt(sum_i w_i (yhat_i-y_i)^2) / sqrt(sum_i w_i y_i^2)

R2 = 1 - sum_i (y_i-yhat_i)^2 / sum_i (y_i-mean(y))^2

For the current prototype release, leaderboard rank uses the higher-is-better composite score overall_score = clip(100 * (1 - total_error), 0, 100). This provisional transformation preserves the ordering of the source-compatible eight-quantity error while giving every FluidsBench dataset the same ranking-column ID. total_error and all component metrics remain visible alongside it.

Dimensional MAE/RMSE columns are intentionally not enabled until FluidsBench fixes a canonical public denormalization and unit convention for every VKI-LS59 output.
